# Bug Fix Skeleton: BUG-003 (Mana Generation Wipe)

## Bug Summary
Mana generated by player basic attacks during the **Execution Phase** is intended to replenish the team's shared mana pool for subsequent rounds. However, at the end of each round, the `transitionToPlanningPhase` function calls `refreshMana`, which unconditionally resets `remainingMana` to `maxMana`. 

This makes the mid-round mana generation mechanic non-functional, as any mana "earned" during execution is immediately overwritten by the full reset before the next **Planning Phase** begins.

**Impact:** Team-wide mana management is simplified to a per-round budget, making basic attacks' mana-generating utility useless.

## Root Cause
In `src/core/services/QueueBattleService.ts`, the `transitionToPlanningPhase` function (L480+) concludes by calling `refreshMana(nextState)`. 

The `refreshMana` function (L195) is implemented as:
```typescript
export function refreshMana(state: BattleState): BattleState {
  return updateBattleState(state, {
    remainingMana: state.maxMana,
  });
}
```
This reset contradicts the combat system documentation (`docs/compendium/systems/combat.md`) which states: *"No regen: Mana doesn't regenerate per round"*.

## Files to Modify
- `src/core/services/QueueBattleService.ts`

## Fix Strategy
Remove the call to `refreshMana` within `transitionToPlanningPhase`. This ensures that:
1. Unspent mana from the previous Planning Phase carries over.
2. Mana generated by basic attacks during the Execution Phase is preserved for the next round.
3. The "No regen" rule is properly enforced, making mana a persistent resource that must be managed and earned.

## Code Sketch

### `src/core/services/QueueBattleService.ts`

```typescript
/**
 * Transition back to planning phase for next round
 */
function transitionToPlanningPhase(state: BattleState): BattleState {
  // ... (existing logic for Djinn recovery and stat clamping)

  const nextState = updateBattleState(state, {
    phase: 'planning',
    roundNumber: state.roundNumber + 1,
    currentQueueIndex: 0,
    queuedActions: createEmptyQueue(updatedTeam.units.length),
    queuedDjinn: [],
    executionIndex: 0,
    playerTeam: updatedTeam,
    djinnRecoveryTimers: updatedTimers,
  });

  // FIX: Remove the refreshMana call to allow mana persistence
  // return refreshMana(nextState);
  return nextState;
}
```

## Test Cases

### 1. Mana Persistence Test
- **Setup:** Start a battle with 10/10 mana.
- **Action:** Queue actions totaling 4 mana. (Remaining: 6)
- **Execution:** No basic attacks occur.
- **Expected:** Round 2 starts with **6/10** mana.

### 2. Mana Generation Test
- **Setup:** Start a battle with 10/10 mana.
- **Action:** Queue actions totaling 10 mana. (Remaining: 0)
- **Execution:** Perform 3 basic attacks (generating 3 mana).
- **Expected:** Round 2 starts with **3/10** mana.

### 3. Mana Cap Test
- **Setup:** Start a battle with 10/10 mana.
- **Action:** Queue actions totaling 2 mana. (Remaining: 8)
- **Execution:** Perform 4 basic attacks (generating 4 mana).
- **Expected:** Round 2 starts with **10/10** mana (properly clamped by `maxMana`).

### 4. Regression: Initial State
- **Setup:** New battle starts.
- **Expected:** Round 1 starts with **Full Mana** (as set by `createBattleState`).
