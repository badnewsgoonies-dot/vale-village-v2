# Mechanics & Data Audit

**Date:** 2026-01-02
**Inspector:** Gemini CLI Agent

## 1. Game Data Definitions

### **Units (`units.ts`)**
- **Total Playable Units:** 10
- **Roles:** Clearly defined roles (e.g., `Defensive Tank`, `Elemental Mage`, `Healer`).
- **Growth Rates:** Defined per unit for HP, PP, ATK, DEF, MAG, SPD. This matches the "Golden Sun" style progression.
- **Ability Sets:** Each unit has a bespoke move set unlocking from Level 1 to 20.

### **Abilities (`abilities.ts`)**
- **Count:** ~145 distinct abilities.
- **Categorization:** Physical, Psynergy, Healing, Buff, Debuff, Summon.
- **AI Integration:** Abilities include `aiHints` (`priority`, `target`, `avoidOverkill`) to drive enemy behavior.
- **Complexity:** Supports advanced mechanics like `ignoreDefensePercent`, `splashDamagePercent`, and multi-hit attacks.

### **Djinn System (`djinn.ts`, `djinnAbilities.ts`)**
- **Count:** 12 primary Djinn (23 defined in code, but 12 mapped to active story timeline).
- **States:** `Set`, `Standby`, `Recovery`.
- **Synergy:** `calculateDjinnSynergy` dynamically adjusts unit class (`classChange`) and stats based on the *combination* of equipped Djinn elements (e.g., "Venus Warrior" vs "Hybrid").
- **Summons:** Activating Djinn allows summoning powerful spirits (e.g., "Judgment", "Thor").

### **Story & Recruitment (`recruitmentData.ts`, `storyFlags.ts`)**
- **Structure:** Linear progression through 30 "Houses".
- **Recruitment:** Triggered by specific encounters (e.g., `house-02` unlocks Mystic).
- **Flags:** Granular story flags track encounter completion and boss defeats to unlock Djinn and progression paths.

## 2. Visual Assets (`public/sprites`)

The asset library is extensive and well-organized:
- **Buildings:** Town structures for every major location (Vale, Tolbi, Imil, etc.).
- **Overworld:** Animated sprites for all 10 playable characters + NPCs (Kraden, Wise One).
- **Battle:**
    - **Party:** Back-view sprites for all characters.
    - **Enemies:** Front-view sprites for a wide bestiary (Ghouls, Dragons, Soldiers).
    - **Summons:** Spectacular full-screen animations (Judgment, Eclipse).
- **UI:** Comprehensive icon set for items, abilities, and interface elements.

## 3. Mechanics Implementation

### **Damage Formulas (`damage.ts`)**
- **Physical:** `(Base + ATK - DEF*0.5)`
- **Psynergy:** `(Base + MAG - DEF*0.3) * ElementMod`
- **Healing:** `(Base + MAG)`
- **Note:** "Zero Elemental Resistance" logic is currently active (stubs return 0).

### **Battle Logic (`QueueBattleService.ts`)**
- **Phases:** Planning -> Execution (SPD sorted) -> Resolution.
- **Mana:** Shared team pool, generated by basic attacks.
- **Djinn:** Toggling Djinn changes stats immediately (re-calculates class/stats).

## 4. Conclusion
The game features a deep, "Golden Sun"-inspired RPG system. The mechanics are not just "foundation" but fully fleshed out with complex data relationships (Djinn class changes). The visual assets support this depth with a massive library of sprites. The "House" progression is the primary content spine, while the "Tower" (Sanctum) serves as a replayable challenge mode.

## 5. Post-Implementation Audit: Zero Elemental Resistance
**Date:** 2026-01-02
**Status:** Implementation Complete, Cleanup Required

The removal of Elemental Resistance logic and the neutralization of damage multipliers (1.0x) has been verified in `damage.ts`. However, significant artifacts remain in the codebase that require cleanup to avoid confusion and "dead" gameplay elements.

### **Dead Data & Schema**
- **Schemas:** `UnitSchema.ts` and `AbilitySchema.ts` still contain `elementalResistance` field definitions.
- **Abilities:** Many abilities in `abilities.ts` and `djinnAbilities.ts` still retain `elementalResistance` modifier fields.
    - *Example:* `Earthen Wall`, `Dragon Scales`.
- **Descriptions:** Ability descriptions incorrectly promise resistance gains (e.g., "Boosts Fire Res").

### **UI Artifacts**
- **BattlePortraitRow.tsx:** Still attempts to map `elementalResistance` to a `Venus_Star.gif` icon.
- **DevModeOverlay.tsx:** References "Act 2: Resistance", which is now obsolete.

### **Gameplay Effectiveness**
- **Useless Abilities:** Defensive abilities that solely granted resistance are now functionally useless.
    - *Action Required:* These must be reworked to provide other benefits (e.g., Defense boost, Shield HP) or removed.
- **Items:** Equipment that previously granted resistance (if any) now provides no benefit in that slot.

### **Code Cleanup**
- **`damage.ts`:** `calculateTotalEquipmentElementalResistance` exists but returns 0. It should be removed entirely once call sites are cleared.
