## Overview
`vale-village-v2` is a Preact port of a Golden Sun-inspired RPG that layers deterministic core logic (`src/core/`) beneath a browser-driven UI (`src/ui/`). Root-level folders such as `docs/`, `scripts/`, `tests/`, `coverage/`, and `public/` host documentation, automation, QA artifacts, and static assets beside the source tree so the entire experience stays discoverable.

## Entry Points
- `index.html` supplies the Vite template and canvas for the SPA shell.
- `src/main.tsx` validates game data, exposes helpers in development, wires legacy and new stores, and renders `<App />` inside `ErrorBoundary`.
- `src/App.tsx` orchestrates global routes/views, game flow slices, overlays, and store synchronization so the UI registers in one place.
- `tests/setup.ts` boots Vitest/Playwright helpers (expect extensions, environment flags, data sinks) before any suite runs, making it the canonical test entry point.

## Directory Summaries
- `docs/`: curated explanations, HOWTOs, and strategic notes that orient contributors.
- `docs/encyclopedia/`: this page plus `file_inventory.json`, the canonical metadata for rediscovering the repo layout.
- `src/`: the writable application tree; subdivided so deterministic logic, data, graphics, and flows never learn about each other’s internal details.
- `src/core/`: deterministic game logic (models, algorithms, services, validation) that can be exercised by code or tests without UI dependencies.
- `src/data/`: shared definitions, schemas, and constants for abilities, enemies, encounters, shops, and other content-driven sources of truth.
- `src/game/`: high-level flow controllers, menu routers, and scene coordination helpers that keep campaigns consistent.
- `src/scenes/`: scene implementations that instantiate flows, cameras, and transitions (e.g., overworld, house interiors).
- `src/systems/`: reusable systems such as `SceneTransitionManager` and `InputLock` that span multiple scenes or UI flows.
- `src/ui/`: Preact components, hooks, sprites, overlays, and state slices that render every screen from battle to compendium.
- `src/infra/`: browser and platform adapters (e.g., `LocalStorageSavePort`) plus infrastructure keepers that sit between the game and the host.
- `public/`: static assets (sprite sheets, manifests, fonts, GIF libraries) referenced by Vite.
- `dist/`: Vite build output plus generated screenshots and sprites used for marketing or QA demos.
- `coverage/`: Vitest/Vite coverage artifacts, HTML viewers, and trace bundles for debugging instrumentation.
- `mockups/` and `screenshots/`: design references and QA captures that document current UX states.
- `scripts/`: developer automation (battle simulators, screenshot captures, tower tooling) runnable with `ts-node`.
- `tests/`: Playwright E2E specs, Vitest unit suites, helper modules, and recorded artifacts (videos, traces).
- `test-results/`: replay archives and snapshot metadata created by the Playwright harness.
- `vale-village-v2/`: legacy Golden Sun reference assets (village layouts, sprite data) kept beside the modern build for comparison and reuse.
- `node_modules/`: pnpm’s dependency cache coupled to `package.json`/`pnpm-lock.yaml`.
- Root configs (`package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `tsconfig.json`, `vite.config.ts`, `vitest.config.ts`, `playwright.config.ts`) declare dependencies, workspace membership, and build/test settings.
